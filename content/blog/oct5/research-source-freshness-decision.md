# Decide when a research source is too old for the question

An older source is not automatically obsolete, and a newly published page is not automatically better. The useful question is whether the source still supports the exact claim a customer decision depends on. A Filipino research assistant can test dates, scope, replacements, and change signals. The decision owner should still approve material conclusions when evidence is incomplete or contested.

## Break the request into claims

Do not assign one freshness label to an entire report. Separate its claims first. A definition, historical event, current price, software procedure, legal requirement, market statistic, and expert recommendation age at different speeds. One document can contain an enduring method beside a number that changed last month.

For each claim, record its wording, decision use, jurisdiction or population, period covered, source, publication date, last-updated date if meaningful, and the date it was checked. Add the event that would make it stale. A policy claim may change when a regulator issues a replacement. A platform instruction may change after a product release. A historical date does not become false merely because another year passes.

The assistant should quote or paraphrase only enough context to show what the source supports. A source mentioning remote work does not automatically support a precise claim about current security controls, productivity, or Philippine staffing. Match the evidence to the claim before debating age.

## Classify the source's job

Use categories based on function. Foundational sources define a framework, standard, or method. Historical sources document what happened at a particular time. Current-state sources describe rules, prices, product behavior, officials, or statistics that can change. Interpretive sources explain evidence but may not control the underlying fact.

A foundational source may remain useful for years if it has not been withdrawn and the cited principle remains in scope. It can still need a newer companion that shows current implementation. A historical source should retain its original date; replacing it with a recent summary may weaken provenance. A current-state source needs a tighter check because accuracy depends on what is true now.

Record status rather than using a vague tag such as old. Useful outcomes are `current for this claim`, `historical evidence`, `foundational—check successor`, `superseded`, `current status not confirmed`, and `outside scope`. These labels tell the writer what to do next.

## Search for replacement and contradiction

Begin with the issuing organization. Check whether it marks the source as archived, withdrawn, superseded, corrected, or incorporated into a newer publication. Search its publication register, standards catalog, policy page, or release notes. A new page with a similar title is not necessarily a replacement; look for an explicit relationship.

Then search for current primary evidence using the claim's key terms, jurisdiction, and subject. Compare definitions, coverage dates, and methodology. If a recent statistic uses a different denominator, it cannot simply replace the old number in a trend. If a new security framework changes organization but retains a cited concept, the original source may still explain history while the new source supports present guidance.

Look for contradiction, not only confirmation. Record credible evidence that narrows or challenges the claim. The assistant should not hide a conflict by choosing the newest result or the source with the most convenient conclusion. Present the difference to the owner and identify which decision changes if one source is preferred.

## Work through a mixed-age example

Suppose a role brief cites a five-year-old remote-work report for two statements. The first says remote teams need explicit communication and handoff expectations. The second says a particular collaboration product uses a named security setting by default.

The management principle may still be useful if the report remains authoritative and later guidance does not reverse it. The product-default claim is changeable and should be checked against current official documentation. Keeping or rejecting both statements together would be careless because their freshness risks are different.

The assistant records the first as foundational, searches for a successor or current companion, and limits the wording to what the report actually studied. For the second, the assistant checks current product documentation and release notes. If current documentation is unavailable or ambiguous, the draft should say the setting must be verified in the customer's tenant, not repeat the old default as fact.

Now imagine that a newer report uses a different population and reaches a different conclusion about remote-work outcomes. The assistant should not call it an update without comparing methods. Show the populations, periods, measures, and limitations side by side. The research owner decides whether the original claim should be narrowed, replaced, or removed.

## Set review dates from change signals

A fixed annual review is easy to administer but can be wrong in both directions. It may leave a fast-changing platform claim stale for months while repeatedly reviewing an unchanged historical source. Tie review timing to likely change and consequence.

Use triggers such as a regulator announcement, new standard edition, platform release, pricing revision, election, scheduled dataset update, contract renewal, or reported broken link. Add a backstop date when no clear trigger exists. High-consequence current claims deserve shorter intervals and a named owner.

The review record should say what was checked and what was not. A live URL proves only that a page responds. Confirm the relevant passage, version, effective date, and scope. Web pages can keep the same address while their content changes. Preserve the allowed evidence needed to explain the earlier decision without copying entire copyrighted works.

## Write conclusions with honest time bounds

Use dates in the sentence when the fact is time-bound. State that a source reported a value for a particular period rather than implying the value is current. For a rule, identify the jurisdiction and effective date checked. For platform behavior, tell the reader to verify the current configuration when tenant settings can differ.

Do not inflate certainty with phrases such as latest research unless the search was broad and documented. Prefer precise language: `the issuing agency's current page checked on October 5`, `the 2024 dataset reports`, or `the standard remains listed as current`. A bounded statement is more useful than an unsupported claim of comprehensiveness.

Keep the source link close to the claim and include enough title information for a reader to identify it. If the source is superseded but historically necessary, label it. If no current authoritative answer is available, say so and route the uncertainty instead of filling the gap with a secondary article that cites no evidence.

## Review the assistant's judgment

Test the workflow with an enduring definition, withdrawn standard, current price, revised law, rolling dataset, changed software setting, and historical event. Predetermine the correct status and the search evidence needed. Include one newer source that is less relevant, so publication date alone cannot determine the answer.

Measure claim-source fit, successor checks completed, contradictions surfaced, date and scope errors, owner corrections, and stale claims caught before publication. Do not reward the number of recent links. Ten new but irrelevant pages are worse than one authoritative source that directly supports the claim.
